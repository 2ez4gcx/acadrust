# Validation Results

Tested on Windows with BricsCAD Ultimate 20.1.07.73135. The native runner used
separate hidden processes and synthetic documents generated by
`examples/issue_regressions_bricscad.rs`. No GitHub issues were closed.

## Rust

- Default features: 1,777 tests passed, 35 documentation examples ignored.
- All features: 1,840 tests passed, 41 documentation examples ignored.
- Issue integration regressions: 35 tests passed, with additional wire-width
  and plain-dash unit tests in the library suite.
- All targets and all features checked successfully.
- Default and all-feature WebAssembly library builds checked successfully.
  Both report the existing unused `sheet_set::normalize_path` warning.

The issue tests exercise ASCII and binary DXF, supported DWG versions, repeated
format conversions, independently encoded ACIS wire data at every bit offset,
malformed counts, every defined affected OEM byte, more than 17,000 Johab
mappings, all 255 indexed named colors, nested INSERT attributes, and XDATA on
all nine symbol tables.

The modern DWG suppression failure also occurs when BricsCAD saves and reopens
its own suppression-enabled TABLESTYLE. `create_style_fixture.lsp` reproduces
that behavior. The runner keeps the suppression checks strict.

The legacy binary load and DIMSTYLE audit failures remain unresolved native
interoperability limitations. They are not counted as successful tests.

Issue #129's original private drawings were unavailable. The wire-width fix is
verified against independent format encodings and native solid volume, but
does not prove every ACIS layout decodes. A separate BricsCAD-resaved modeler
fixture still produced an array-count error in acadrust; further ACIS layout
work remains necessary for that fixture.
