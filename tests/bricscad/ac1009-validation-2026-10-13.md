# AC1009 Native Validation, October 13, 2026

Validated with AutoCAD 2027 Core Console 26.0.118.0.0 on Windows.

```powershell
cargo run --example r12_native_fixtures
pwsh -NoProfile -File tests/bricscad/run_r12_native.ps1 -SkipGenerate
```

All seven files retain the AC1009 signature. Each opened without import
recovery, completed AUDIT with **0 errors found, 0 fixed**, passed its geometry
checks, and exited normally. The harness operates on copies; source DWGs are
not saved or upgraded by AutoCAD.

AutoCAD converts the legacy 2D polyline into LWPOLYLINE during import; the
validator accepts either representation and compares the vertices.

Native testing identified defects which encoder/decoder agreement had hidden:
main-file return JUMPs need absolute addresses, native STYLE flag bits must not
be swapped, system-space and ByLayer/ByBlock records must not be emitted as
ordinary R12 table entries, the imported AcadAnnotative default causes a
duplicate APPID, and HANDSEED must include generated child handles. Empty
tables and fresh legacy header settings also require valid native defaults.

The fabricated block-owned extra/JUMP layout was rejected by AutoCAD and is
not included among these native-positive files. That branch remains covered
only by structural section-walker tests pending corroboration from actual
native drawings. Unsigned reference boundary tests and arbitrary opaque
header bytes are likewise parser cases, not exported drawing fixtures.

Per-file reports, console logs, and machine-readable results are generated
under `target/ac1009-native`. These results establish the listed cases, not
exhaustive R12 conformance.

## Drawings Created Inside BricsCAD

The extended corpus was drawn inside BricsCAD V20.1.07 and saved as native
AC1009 using `acR12_dwg = -3`. Six companion DXFs were exported independently
using `acR12_dxf = 1`. Seven original DWGs and seven acadrust resaves all passed
AutoCAD 2027 opening, geometry/state checks, and AUDIT with zero errors and
zero repairs. Sources and generation provenance are retained in
[the native corpus instructions](../fixtures/r12/cad-created/README.md); DWG
binaries are generated on demand and are not checked in.

The cases include compound blocks and attributes, 2D/3D polylines, polygon and
polyface meshes, four paper-space viewports, view/snap/grid settings, named UCS
and VIEW records, edited variants, and repeated native Save operations.
The native sources revealed unnamed BLOCK markers, shared VX/BLOCK sentinel
placement, mesh-vertex classification/layer loss, MVIEW radians, paper-space
routing, address rebasing and padded numeric XDATA defects.

Native QSAVE with ISAVEPERCENT=100 still produced no extra-stream records.
The historical relocated-block layout is therefore not claimed validated.

## October 14 Import-Parity Recheck

After adapting Ottosson's `641ec9c` and `86cfbbd` import fixes, the seven native
drawings were resaved with the updated library. All 14 original/resaved DWGs
again passed clean AutoCAD 2027 opening, geometry/state checks, and AUDIT with
zero errors and no repairs. This run used the same commands and corpus above;
the refreshed results were written to the temporary `target/ac1009-cad-created`
directory and are not checked in with the DWG binaries.

Rust regressions separately check explicit code-page decoding, declared-page
metadata, three save/reopen cycles, fixed-header overflow rejection, newer-DWG
isolation, and synthesized layout defaults for both handle-storage modes and
the BricsCAD viewport drawing. The native harness establishes opening and
geometry/state interoperability; it does not assert host-dependent encoding
behavior for deliberately mismatched declarations.
